# BIP39-D20 — Generate a Seed Phrase with a 20-Sided Die

**English** · [Español](README.es.md) · [Italiano](README.it.md) · [Português (BR)](README.pt-BR.md)

**Official repository:** [github.com/Yuri-SVB/BTC-D20](https://github.com/Yuri-SVB/BTC-D20)

A printable two-page kit for generating a 12-word [BIP-39](https://github.com/bitcoin/bips/blob/master/bip-0039/bip-0039.mediawiki) seed phrase with nothing but a 20-sided die (D20), a pen, and paper:

- **Instructions sheet** (front) — available in English, Spanish, Italian, and Brazilian Portuguese, in a standard (12-word) and an extended edition (12 & 24 words, plus the last-word-completion shortcut).
- **Lookup table** (back) — all 2048 BIP-39 words arranged as an 8 × 16 × 16 coordinate system.

Every roll you keep is entropy you saw with your own eyes. No electronic random-number generator is involved in choosing your words.

## Why verifiable entropy (and why now)

In July 2026, over a thousand BTC were swept in minutes from wallets whose seeds had been generated by Coldcard devices. A firmware flaw present since March 2021 had silently routed seed generation to a predictable software PRNG instead of the hardware RNG, so those seeds carried far less than the promised 128 bits of entropy ([CoinDesk](https://www.coindesk.com/tech/2026/07/31/major-bitcoin-wallet-flaw-drains-594-btc-in-25-minute-sweep), [The Hacker News](https://thehackernews.com/2026/08/coldcard-hardware-wallet-flaw-linked-to.html)).

Two facts from that incident frame this tutorial:

1. **The failure class, not the brand, is the lesson.** The vendor patched within a day. But no user could have *seen* the bug: electronic entropy is invisible by nature. Any device, from any vendor, asks for the same blind trust at seed-generation time.
2. **Dice were never at risk.** The vendor's own advisory notes that seeds generated from 50+ fair dice rolls were unaffected. Physical randomness that you watch happen is the one entropy source that needs no audit.

This method produces the full 128 bits of a 12-word seed from ~35 valid D20 rolls, with uniformity guaranteed by rejection sampling (rolls of 17–20 are discarded).

## How it works

Each BIP-39 word is addressed by three die rolls, keeping only results 1–16:

| Coordinate | Selects | Valid results per outcome | Bits |
|-----------|---------|--------------------------|------|
| **D1** | one of 8 page sections | 2 (sections are labeled "1,2" … "15,16") | 3 |
| **D2** | one of 16 rows | 1 | 4 |
| **D3** | one of 16 columns | 1 | 4 |

Eleven words are rolled fully (11 × 11 = 121 bits). For the twelfth word only D1 and D2 are rolled (7 more bits, totaling 128); its column encodes the 4-bit checksum, so exactly one of the 16 words in the selected row completes a valid seed — found by trial and error in the wallet's seed-entry wizard.

The **extended editions** additionally cover 24-word seeds — words 1–23 fully rolled (253 bits), D1 only for the 24th (3 more bits, 256 total; 70 valid rolls), with exactly one valid word per 256-word section — and the **last-word-completion shortcut**: tools such as SeedSigner's *final word* flow, [SeedPicker](https://github.com/merland/seedpicker), [Coinplate's offline BIP39 Recoverer](https://github.com/Coinplate/BIP39-Recoverer-Seed-Phrase-Recovery-Tool) or [Ian Coleman's page](https://iancoleman.io/bip39/) (offline) list the valid final words, of which there are always exactly **128 for a 12-word seed (one per table row)** and **8 for a 24-word seed (one per section)** — so a D1(+D2) roll picks yours. They also link the companion post [*No Quiet Fix: Kerckhoffs' Lemma and the July 2026 Seed-Entropy Incident*](posts/kerckhoffs-lemma-coldcard.md).

Both worked examples printed in the instructions — and the 128/8 candidate counts above — are machine-verified by [`tools/verify_tutorial.py`](tools/verify_tutorial.py) against the official wordlist and checksum algorithm.

**Table integrity is structural, not asserted.** No copy of the word data exists in this repository: the build reads `bip-0039/english.txt` directly out of the canonical [`bitcoin/bips`](https://github.com/bitcoin/bips) repository, mounted at `external/bips` as a git submodule pinned to an exact commit and fetched sparse, so only `bip-0039/` ever lands on disk — the words in the printed table are anchored by git's own hashing to upstream history, and `make verify` additionally cross-checks the file against the BIP-39 reference SHA-256. Audit it yourself: `git submodule status` and `sha256sum external/bips/bip-0039/english.txt`.

## The color system

The table's cells are shaded so the eye can track coordinates across a dense 2048-cell grid. Three parity bits select one of eight shades:

- **Column parity → hue**: odd columns yellow, even columns orange.
- **Row parity → brightness** (large step) and **section parity → brightness** (small step).

Row-label, section-label, and header cells follow the same logic at different saturations, and the D1 label column is shaded by section parity across its whole 16-row block. The scheme is implemented programmatically at compile time: [`table/bip39-table.tex`](table/bip39-table.tex) reads the official wordlist straight out of the commit-pinned `bitcoin/bips` submodule and derives every cell's word and color from its (section, row, column) coordinates with document-level loops — no generated intermediates, no hand-encoded words. Tuning the palette means editing the parameter block at the top of that file.

## Building

Requires TeX Live (with `fontawesome5`, `qrcode`, `tcolorbox`, and the babel language packs) and Python 3. On Debian/Ubuntu:

```sh
sudo apt-get install --no-install-recommends \
  texlive-latex-base texlive-latex-recommended texlive-latex-extra \
  texlive-fonts-extra texlive-lang-european texlive-lang-portuguese \
  texlive-lang-spanish texlive-lang-italian latexmk
```

Then:

```sh
make            # build table + all four instruction editions into dist/
make en         # a single edition (en, es, it, pt-br)
make table      # lookup table only
make verify     # wordlist integrity + worked-example checks
```

The word data comes from the `bitcoin/bips` submodule, and `make` fetches it automatically when missing — minimally: only the pinned commit, blob-filtered, with only `bip-0039/` checked out (a few hundred KB, never the whole repository). A regular `git clone --recurse-submodules` (shallow) works too.

CI runs `make verify` and rebuilds every PDF on each push, uploading them as artifacts. Ready-to-print PDFs are also committed under [`dist/`](dist/).

## Printing

Print the instruction sheet in your language and the table double-sided (long-edge binding), A4. The table is intentionally `\tiny` — print at 100 % scale, no fit-to-page shrinking.

## Security notes

- Perform the procedure in private; never photograph or digitize rolls or intermediate results.
- Only ever type the finished seed into a trusted, air-gapped device that you own.
- If you suspect an existing seed came from flawed software or firmware, generate a fresh seed with this method and move funds to it. Firmware updates cannot repair weak seeds.
- The example seed printed in the instructions is public. Never use it.
